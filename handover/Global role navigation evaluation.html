Corrected behavior

  • Staff: Project Tasks → View tasks and add task → Create Task saves and returns to that same project task page. Staff navigation remains Staff navigation even when the account also has superuser permissions; those permissions are preserved.
  • Task and project actions accept a validated origin in the same feature. Foreign sites, unrelated dashboards, inaccessible projects and unknown shared sections cannot become return destinations. Board assignee filters and relevant query strings are preserved.
  • Invalid task and assignment forms keep their workspace and errors. A Kanban validation error reopens the task modal on the board instead of sending the user to project assignment.
  • Project allocation removal uses an existing project list destination. Supervisor-role fallbacks use the caller’s own home. Shared publication, template and resource pages use the primary role’s navigation.
  • Student notices use a separate POST route, store the read receipt, show the actual notification body and return to Notifications. Dean paper mutation controls and the unavailable Add Book control are hidden to match existing server permissions.
  • Duplicate sidebar code and unused demo scripts were removed from the affected PM, Student and Gantt pages. Finance analytics now receive JSON instead of Python values, with numeric amounts normalized. Incorrect local background paths were corrected.

Communique and purposeful shared pages

Shared pages remain shared. Communique Back returns from a section to the Communique tiles; Back from the tiles goes to the user’s own home. Templates uploads, including error cases, return to Templates. Availability and messaging saves use their existing shared APIs and remain in the current section. Communique sets the security cookie required for protected saves even in a fresh non-Admin session.

IT can use staff messaging as well as the shared pages already offered in its menu. Students retain the assigned-supervisor communication boundary: the shared Messages section offers a working link to their own supervisor chat instead of staff compose/broadcast buttons that their account cannot use. Students do not gain the staff messaging directory.

User journeys after the fixes

  1. Staff opens Project Tasks, selects an assigned project, enters a task, optionally selects an existing parent task for a subtask, and presses Create Task. The success message and shared task table appear on the same page.
  2. Financial Admin opens My Projects or My Project Kanban. Creating work from a project returns to that project; creating work from the board returns to that board. Admin’s selected assignee stays selected after a save or validation error.
  3. Any permitted account opens Communique and chooses Availability, Messages or Templates. Shared actions keep the feature context. Back goes to the tiles and then the appropriate role home.
  4. Student opens Notifications and presses Mark as read. The read receipt is saved and the portal remains at Notifications. Supervisor conversations stay in the Student portal.

Coverage limits and release checks

The audit inventories visible menu links and rendered form destinations and executes representative create/update/delete, validation and permission scenarios. It does not execute every button against every possible record, browser, account history or concurrent state. No production rows were changed by this navigation evaluation. The earlier production rollback-only financial self-assignment evidence remains separate.

Real SMTP delivery, live Azure/Azurite upload delivery, production PostgreSQL restore, load, penetration, accessibility and business-owner UAT sign-off are separate checks. Login, logout, password/security verification, downloads and a database restore may intentionally leave the current page; a successful restore requires reauthentication. A Git push alone does not prove Render has deployed the revision.
